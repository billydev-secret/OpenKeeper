# Documentation Index

This folder holds the specs, deployment notes, and audits for Dungeon Keeper. Feature specs live in `specs/`, one file per feature; the documents at this level are the how-we-work ones: the design guide, the dev and ops docs, the style guides, the data register. It has grown organically alongside the bot, so the documents here are **not all equally trustworthy**. Some describe the bot as it runs today, others describe what we *planned* to build, and a few describe features that were never fully built.

> **⚠️ Read this first: specs come in three flavors**
>
> - **Reference**: matches current behavior. Safe to treat as documentation.
> - **Design spec**: written *to implement* a feature. The feature usually exists, but the spec may lag behind the code in details. Verify against the source before relying on specifics.
> - **Aspirational**: documents things that were never fully built. Read with care: commands, modules, and flows described here may simply not exist.
>
> Each entry below is classified. When in doubt, the code wins.

**Building a feature? Start with [design_guide.md](design_guide.md).** It holds the order of the decisions, the coding standards and the pre-commit obligations, and points at whichever doc below owns each detail.
