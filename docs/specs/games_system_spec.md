# Games System — Feature Spec

A 17-mode party-games suite. Every mode is one subcommand under a single top-level `/games` command group: players start a game with `/games play <slug>` (e.g. `/games play ffa`), which spins up a public embed with buttons; players join and play in-place. Games share a per-channel session window for the `/recap` highlight reel, a per-channel allowlist and per-guild enable/disable matrix (both managed from the web dashboard), an optional audit channel for anonymous content, a question bank for prompts, and a dashboard for content authoring. Bank draws are round-robin (least-recently-served row first, so a small pool doesn't repeat until every row has been served once; see **Question-bank / AI-augmented games**). Games also feed the economy: completing quest-relevant actions credits economy quest triggers (see **Economy integration**).

The companion 1-v-1 nickname duel **Pressure Cooker** and the dice game **Risky Rolls** appear in the shared game registry (`GAME_ICONS`/`GAME_NAMES`) but are **separate features** with their own entry points and specs; they are not part of this suite. See [[pressure-cooker-spec]].

> **Command surface.** Only the `games` group is registered to the command tree (`command_groups.py`). Party games hang off the nested `games play` subgroup; meta/admin commands hang directly off `games` or its `config`/`dev` subgroups (there is no `track` subgroup; see External Tracking below). `/recap` and `/support` are top-level commands. There is no bare `/ffa`, `/wyr`, ….

A game whose lobby is a V2 card frames it with the guild's **Lobby Header** and panel footer when an admin has uploaded a header (Branding → Panel Art): `games/utils/lobby_art.read_lobby_art(bot, channel, title)` reads it and draws the game's name into the header (the lobby then drops its `##` heading; an age-gated channel wears it too, unspoilered) and `core.layout.lobby_art` places it; the builder joins `LOBBY_ART_BUILDERS` in `tests/contracts/test_layout_hub_banner.py`. Clapback, Compliment Circle, MFK, Story Builder, Truth or Dare's room board and the duels layer's group lobby (every BaseGame mini-game) wear it, and a BaseGame mini-game wears it on every card of the game, challenge to result, which it edits into one message (`dk_pvp_games_suite_spec.md` § One card); `tests/games/test_games_lobby_art.py` pins the frame each builder puts it in.

External tracking is a format-agnostic collector (configured on the dashboard panel; there are no `/games track *` commands): an `on_message`/`on_message_edit` listener banks every message from a watched channel+bot RAW (keyed on message id, de-duplicated across restarts/edits) into `games_external_messages`. Nothing is parsed at ingest; metrics are derived later, so a format change never loses history. Each watch carries a `kind` selecting a parser (`games/external/parser.py`); migration 097 generalized the one-bot-per-guild table to multiple `(channel, bot, kind)` rows, and **migration 135 widened its key to `UNIQUE(guild_id, bot_user_id, channel_id)`** so one bot can be watched in many channels; the collector cache is keyed on the `(bot, channel)` pair to match.

**Concurrency.** Games running at the same time in different channels each pay out independently, and need no coordination to do so: every payout is a pure function of its own channel's banked history (`recent_channel_messages` filters by channel), so N channels is just N independent backward scans. Nothing is tracked while a game is in flight: there is no game registry, and no state survives between messages.

**`gamebot` is live** (the kind was `gamebot_cah` before it covered three sub-games), covering three sub-games that share one Discord bot account: Cards Against Humanity, Connect 4 and Anagrams. Every terminal message (`is_terminal`) goes through the single `_pay_gamebot_game` entry point, which reconstructs the game's window (`current_game_window`) and identifies the sub-game (`identify_game`) before dispatching:

- **Window bounding is anchored on the game's own lobby embed** (`<host> is starting a <Game> game!`), walking back from the terminal and stopping at that lobby, or at the previous game's terminal if the lobby has aged out of the banked slice. Anchoring on the lobby means a window holds exactly one game's messages.
- **The sub-game is read off that lobby, never off the terminal message.** CAH and Anagrams end with the *identical* `<@id> is the winner!` wording, so a terminal can't tell them apart, and dispatching on it would credit every Anagrams game as a one-player CAH game at score 0. A lobby naming a game we have no parser for (Chess, Poker, …) yields `None` and pays nobody, rather than falling through to a wrong guess.
- **Abandoned lobbies pay nobody.** `Not enough players joined the game!` still gets a *Game over!* from Gamebot; `is_abandoned` catches it. A roster reader that took the **Joined Players** field off *any* embed would pay an abandoned CAH lobby as a Connect 4 game, so the join-phase reader is gated on its embed titles and shared across sub-games (`players_from_join_phase`), the join phase being identical for all of them.

**Gamebot's CAH format.** Gamebot rewrote every CAH string on 2026-08-15 (an unmatched format paid CAH nothing). The parser speaks both vocabularies, since an older-format game can still be in flight:

| | older format | current format |
|---|---|---|
| standings | *Current Standings* embed, `<@id>: 3` in the description | a **Standings field** on *Round winner* / *Final scores*, `<@id>: **3**` |
| submissions | *Submission status*, `✅ <@id> Submitted!` | a **Submissions field** on *Play your card*, `✅ <@id>` / `⬜ <@id>` |
| finish | *Game over!* + `<@id> is the winner!` | *Final scores*; **no winner is declared at all** |
| lobby roster | **Joined Players** field | **Players (6/12)** field |

Two consequences beyond the string swap. **The winner is derived**, as the top of the last standings, since Gamebot's current format names none; CAH is first-to-N so a completed game has a unique leader, but a game Gamebot drops part-way can leave the lead tied and then *every* tied player wins (`extract_cah_game` returns a **list**, which `pay_cah_game_by_score` already accepts; Wordle ties the same way). An all-zero standings yields no winner at all rather than an N-way tie. **`Something went wrong` is terminal**, so a game Gamebot drops still pays out the rounds that were played (a deliberate call). One posted 1.4s *after* a clean *Final scores* is not a double payment: each terminal claims on its own message id, so what protects the ledger is the window: bounding back from the crash stops at the *Final scores* before it, leaving a one-message window with no standings, which pays nobody.

Connect 4 and Anagrams **have not been verified against the current format**: the last banked Connect 4 lobby predates the change and no Anagrams game has appeared in the archive, which is why `gamebot_anagrams` has no rows. The shared join-phase reader handles both roster field names, but Connect 4's new terminal wording is unknown until someone plays one.

Per sub-game: **CAH** reconstructs final scores (last standings post, folding in submission-only/winner-only players at 0) and calls `pay_cah_game_by_score`: the top scorer earns `EconSettings.reward_cah_win_max` (default 50, dashboard-configurable), everyone else a ratio of it, firing the same `party_game`/`game_win` triggers. Standings are accumulated and never pruned, so a player who leaves mid-game keeps the score they earned and is paid for the rounds they played, even though Gamebot cuts them from every later standings. **Anagrams** reads its *Scoreboard* embed, whose **field names** carry `"<username> - N POINTS"`; players are named by username rather than mention, so they're resolved with `resolve_named_scores` (the same `get_member_named` lookup Cat Bot uses) and then paid through `pay_cah_game_by_score` with `game_key="anagrams"`, sharing the same cap. **Connect 4** reconstructs roster + winner (`<@id> has won!`) and calls the flat `pay_game_rewards` (win/lose only, no score to scale by). All are paid once via a `games_external_payouts` ledger (migration 099) keyed on the game-over message id, independent of `parse_status` (which edit-recapture resets).

**`catbot` is also live**: Cat Bot catches are parsed from message content (`{username} cought <:raritycat:…>`, reverse cats un-reversed, "blessed…doubled" ×2), the catcher resolved by username→member (`get_member_named`), and `pay_cat_catch` credits rarity-tiered coins (common 1 → divine 300) plus the `cat_catch` quest trigger, paid once via the same ledger, keyed on the catch message id.

**`wordle` is live.** The Wordle bot posts one self-contained daily digest per group (no embeds, no lobby), so unlike every Gamebot game this needs *no backward scan at all* and is keyed on the digest's own message id:

```
**Your group is on a 9 day streak!** 🔥 Here are yesterday's results:
👑 3/6: <@490899999999999922> <@83699999999999932>
4/6: <@203899999999999916>
X/6: <@1069999999999999991>
```

Scoring is **inverted** relative to CAH/Anagrams (fewer guesses is better), so `parse_wordle_results` flips it (`1/6` → 6 … `6/6` → 1, `X/6` → 0, which keeps a failed player in the roster for `party_game` while earning no coins) and the shared `pay_cah_game_by_score` does the rest. Ties on the 👑 line are normal, so that function now accepts **several winners**. Wordle mentions only some players and prints the rest as a bare `@Name`; those are split on the `@` (not on whitespace; real display names contain spaces, e.g. `@shared turnip`) and resolved with `resolve_named_scores`. In the observed history that recovers 21 of 22 such entries.

**`coordle` is live.** Co-ordle is a *co-operative* hourly word puzzle whose board embed (`Co-ordle for <t:…:f>`) lists each guess with its player and points. Two properties make it unlike everything else:

- **A new board message is posted per guess**, each showing the whole round. So the payout is keyed on the **round's own scheduled timestamp** (`coordle_game_key`), not a message id (keyed on the message, it would pay the same round once per guess). Those values (~1.7e9) cannot collide with Discord snowflakes (~1.5e18) in the shared ledger.
- **There is no terminal message.** `This Co-ordle has ended` is only a rejection sent to a late guesser. Finality is read off the board: six greens in a row means solved, no unplayed rows left means exhausted. A round that simply times out with rows to spare stays open and never pays (16 of 1,887 observed rounds, the accepted cost of having no end-of-round signal).

Points are the inline `**+N**`, or `**+N (+M)**` where a bonus applies, in which case the player earned **N+M**. That reading was verified against the bot's own cumulative leaderboard across consecutive snapshots: `N+M` reproduced the leaderboard delta for 79% of player-rounds versus 0.5% for `N` alone (the remainder being rounds clipped by a snapshot boundary or its top-10 cut). The leaderboard embed itself is cumulative all-time and is deliberately **not** used for payout, since doing so would re-pay every prior round.

**Host bounty.** Gamebot names whoever started a game in its lobby title (`hostowl is starting a …`) by username, so `host_from_lobby` reads it and the cog resolves it with `get_member_named`. The bounty lives in the shared `pay_host_bounty`, called by both the flat faucet and the score-proportional one: `joiners` counts players *other than* the host, so a game nobody else joined pays nothing (the anti-farm gate, which is also what makes an abandoned lobby pay its would-be host nothing). A backfill of host bounties must be idempotent via a `meta.game` stamp on each `game_host` ledger row (the payouts ledger can't be reused, since it's keyed on the Game-over message id and a game whose *participation* is already paid still owes its host), and booster status has to be passed in explicitly, since it lives only on the gateway (`member.premium_since`) and is recorded nowhere in the database.

**Replaying unpaid history.** A backfill of finished games with no ledger claim (the one-off scripts are deleted; git history keeps them) must feed each game through the *same* parser functions the cog calls, so backfill and live payout can't diverge. It claims before crediting, so a game already paid live is skipped structurally rather than by a cutoff, and fires quest triggers on each game's **own local day** so a backlog doesn't land on today's board at once. **Wordle and Co-ordle have no replay**: their history predates tracking and sat in the general `messages` table rather than `games_external_messages` (migration 228 erased that text, so it cannot be replayed), and paying 1,581 historic Co-ordle rounds at once would be a large unplanned coin injection. Both pay from the moment their watch is configured.

### Dashboard-managed configuration

These settings are **live and enforced** but are configured from the web dashboard (`/api/games/*`), **not** slash commands. There are no slash commands to manage them.

- **Channel allowlist** (`games_allowed_channels`, `guild_id`-scoped as of migration 122). Every *question-bank* game preflights `check_allowed_channel`; the six duel/group games in `dk_pvp_games_suite_spec.md` do **not**; their only channel rule is their own per-game `channel_allowlist`, and their panels say so. A channel that isn't on the allowlist refuses every question-bank game. The dashboard channels panel and the game-history/stats views are filtered to the active guild, so a host of one guild can't see or delete another guild's rows. (Legacy rows predating migration 122 carry `guild_id = 0`, treated as a wildcard by the in-Discord gate but invisible in the guild-scoped dashboard until reconciled.)
- **Per-guild per-game enable/disable** (`games_game_config`, default enabled;
  no row means on). Checked by `check_game_enabled` at the start of every
  game's command **and** by the scheduler before each auto-launch. Set on
  **Games → Global Config → Available on This Server**, which lists every type in
  `routes/games.py:ALL_GAME_TYPES`; games with their own settings page repeat
  the same switch there, and Photo Challenge's lives on its own page instead
  (it is deliberately absent from the list, so the standalone panel stays the
  only writer of its row). The key is the game type string the bot reads, so
  each entry must be spelled exactly as its reader spells it or the switch is
  unreachable (`risky_roll`, not `risky_roller`; `legitlibs` must be in the list or
  its PUT 404s). Every game's start command calls `check_game_enabled`. The six
  duel/group games use the same store, keyed
  by each cog's `GAME_KEY`, checked at both creation entrypoints. **A panel
  labels the switch for everything that reads it.** A `legitlibs` switch labelled
  "Include in Scheduled Games" would let an admin trimming the schedule silently
  kill `/games play legitlibs`, and a `risky_roll` switch under "Available on
  This Server" must really gate `/risky start`. Both panels say "Available on
  This Server", the same words the Global Config list uses for the same row.
- **Player limits are offered only where there is a lobby.** Most Likely To and
  Mt. Rushmore Draft create their game with `state="joining"`, so a floor and a
  ceiling have somewhere to apply; every other game goes straight to
  `state="playing"` and its panel offers neither. Both ceilings are clamped to
  **25** whatever the dashboard stored, because the per-round vote is a Discord
  `Select` and a larger lobby would 400 the message; `mfk` caps its pool at
  the same number, for its own reason (below). Rushmore's Join button must respect the cap: the
  vote roster is sliced at 25, so a 26th player would draft a full board and
  then not be voteable.
  **LegitLibs is the exception that proves the rule**: its ceiling isn't a dial
  but arithmetic on the chosen template's blank count (`ceil(n/10)` to
  `floor(n/5)`, each player filling 5–10 blanks), so the template editor shows
  the range instead of collecting it, and both modes turn away a joiner once
  the lobby reaches it (`validation.lobby_is_full`); the two
  numbers are not editable fields.
- **No dial exists that no cog reads** (17 such dials were removed across WYR,
  AMA, NHIE, Price, Rushmore and Clapback). Three would have been worse than
  inert if wired: WYR's "Hide Who Voted for What" could not do what it said
  (naming is driven by a separate `revealed` flag set by a host/mod button, and
  `anonymous` only gates whether per-vote audit rows are written, so it would
  suppress a mod trail while hiding nothing from members); AMA's cog reads
  `mode`, not `screened`; and a Clapback "Include NSFW Prompts" toggle would
  contradict the house rule that NSFW gates on `is_age_gated_channel()` and never
  on a bot-side toggle.
- **Audit channel** (`games_audit_channel`). When set, anonymous submissions are mirrored there with the original author visible. **Only** anonymous submissions: nothing writes a game-lifecycle event there. It is a *mirror*, not the record: every anonymous action is also written to `anon_audit_log` and surfaced on the admin dashboard regardless of whether this channel is configured (see `anon_audit_spec.md`).
- **Game Host / editor role** (`games_editor_role`). Holders pass the Game-Host check for content authoring on the dashboard and can add/remove other players via `/games join|leave`.
- **LegitLibs per-channel tier cap** (`legitlibs_channel_config.max_tier`, default 4), set per-row on the Games → Global Config → Allowed Channels table, and LegitLibs template authoring. The LegitLibs **blank vocabulary** is not in that list and is not configurable; see *Environment / files* below.

### Dashboard

**Play Statistics** (`/api/games/stats`, route id `games-logs`) reports games played, rounds, unique players and a per-type breakdown, all-time or for the **last 30 days** (`?days=`; the bank count is a library size and is never windowed). The game name / icon map rides with the response (`games`) and the breakdown iterates every type the history holds, most played first (a panel-local copy of the map would draw a missing game, such as Truth or Dare, nowhere; platform-26). **Unique Players** is rebuilt server-side from each archived payload with the payout's own per-game extractors (`game_roster.roster_from_payload`), so it counts members who took part (voted, joined, answered) and not hosts plus whichever payloads happened to carry a `players` list; a photo card carries its poster count in `player_count` but no member ids (`photo` is in `NO_ROSTER_TYPES`), so photo posters are **not** in Unique Players (see `photo_challenge_spec.md`). Meadow Mahjong's settled hands are self-recorded rows (`game_type = 'mahjong'`, human seats under `players`; `mahjong_service`), named **Meadow Mahjong** in `GAME_NAMES` and read by the same extractor, so they count too (the table is not on the games menu, so it has no `GAME_ICONS` entry). The history filter offers every type ever played (`history_types`), so a game that played last year is still selectable inside the 30-day window.

The dashboard mirrors the config surfaces above and adds full LegitLibs template authoring, question-bank import/export, and an AI prep helper for LegitLibs templates (`POST /api/games/legitlibs/ai-prep`). Banks also share a **global pool**: bank rows stored under the reserved `global` game type, which gameplay never selects. Every bank manager has a per-question *Pool* button (copy to the pool; duplicate texts are skipped, and Traditional's category tags are translated to the generic `nsfw` tag or dropped) and a pool browser that imports selected pool questions into that game's bank (duplicates skipped; Traditional requires choosing the category the imports are filed under, other games carry the pool tags over). Two permission tiers gate it: `mod` (Administrator / Manage Server) for config writes, and a Game Host tier (Administrator OR the configured editor role) for content authoring (bank, templates, AI prep, history, stats). FFA's `truth`/`dare` tags are reserved the way `nsfw` is: a truth round draws only rows tagged `truth`, so its bank panel states that contract in its hint rather than enforcing a category the way Traditional does; an untagged FFA row is valid and simply only ever comes up in a random round.

## Behavior

Every interactive game follows the same skeleton: preflight (channel allowlisted? game enabled for this guild?), insert a "live game" row keyed by channel id (`games_active_games`, which carries its `guild_id` since migration 204, stamped by `create_game` from the launcher's guild, or from the channel allowlist when a launcher passes none), post the embed + view, and on close archive the game's final payload into a history table and free the live-game slot. Each channel can host at most one live game at a time. A 24-hour sweep closes orphaned games that nobody closed; closing copies the payload into the history archive and frees the slot. (Photo Challenge is fire-and-forget: it records a history row for stats but keeps no interactive state, since people just reply in the channel.)

The preflight guards **every door into a launch, not just the slash command**. The dashboard scheduler re-checks the enabled dial itself; a **feature-rotation** launch (`feature_rotation_service.start_room_game` → `_launch`) reads `check_game_enabled` against the base game type (`SCHEDULE_BASE_GAME_TYPE`, so a display variant honors its base game's toggle) and logs-and-skips a disabled game; and the recap cards' **Play Again** (Clapback) and **Run Again** (Name Your Price, Mt. Rushmore Draft) buttons go through `game_manager.relaunch_refusal`, which is a thin name for **`games/utils/launch_guard.launch_refusal`**, the one guard every door is meant to share and the single owner of the refusal copy. It runs, in order: allowed channel; the enabled dial (the game named from `GAME_NAMES`, or an explicit `label`); a **busy check**: a game already running in the channel is refused by name with a jump link to its board when the anchor message is known ("❌ There's already a game running in this channel — **Would You Rather** (jump to it). Wait for it to finish, or the host or a mod can `/games end` it first."); and, for the **bank-only** games (`BANK_ONLY_TYPES`: Clapback, Would You Rather, Never Have I Ever, Most Likely To; Rushmore and Name Your Price default to host-supplied material and are deliberately not listed) launched without host-supplied material, an **empty-bank check** through `has_matching_questions` honoring the host's tags and the channel's age-gate, refused with the dashboard hint Clapback already used ("No prompts in the bank for Most Likely To. Add some from the Games question bank on the web dashboard."). It returns the message or `None` and never sends; the caller does. **Every party-game slash entry runs the guard:** Would You Rather, Never Have I Ever and Most Likely To pass the host's tags, the channel's age-gate and `host_supplied` when a `question:` was typed; Clapback passes the age-gate (the guard's bank check is its prompt pre-check); the other twelve (Truth or Dare, Two Truths, AMA, Compliment, MFK, Story Builder, Name Your Price, Mt. Rushmore, ffa/ffa_banner, LegitLibs) pass nothing extra. So a double-tap in a busy channel and a bare `/games play mlt` on an empty bank are refused at the command with the shared copy (platform-18: without it sixteen entries could launch a second board on top of a live one, and Truth or Dare double-started four times in prod; trivia-tail-88; platform-27: a bare `/games play mlt` could fill a lobby and die at Start on an empty bank). ffa keeps its own tag-filter check after the guard (it is not bank-only) but sends the guard's `no_tag_match_message`. No slash entry carries a refusal literal of its own. The scheduler and rotation doors use the guard too, so a host cannot keep a game an admin just switched off alive from the recap card (`docs/reviews/2026-09-02-games-deep-review-findings.md`, safety-sweep-3/4, platform-28).

The games cluster by shape; each cluster shares interaction patterns.

### Question-bank / AI-augmented games

**Would You Rather, Never Have I Ever, Most Likely To, Mt. Rushmore Draft, Name Your Price, Clapback** draw prompts from the pre-seeded bank and nothing else; there is no AI fallback. When the bank has nothing to serve mid-game, **WYR, NHIE and MLT open the round *waiting for a prompt***: the board shows "⏳ No question yet — press ✍️ Pose … to submit one and the round starts" with only Pose, 🏁 End Game and Help live, and the first posed prompt opens that same round in place (`begin_round`); the game never ends itself on an empty bank (vote-games-50: ending on an empty bank would tell the host to use a Pose button that isn't there, and NHIE would pay nobody). A **Would You Rather bank row is `option A | option B`**; a row typed as prose ("Would you rather X, or Y?") is split on its last ", or " / " or " after the "Would you rather" lead-in and trailing "?" are dropped (`question_source.split_wyr_options`, shared with the dashboard, which stores what it can split in the `a | b` shape and refuses what it cannot with the shape spelled out; vote-games-49: all 23 prod rows were prose and a bank-fed game marked one served and ended in the same second). **AMA has no bank**: every AMA question is typed by a member during the game, no draw function reads `game_type='ama'`, so its panel offers no bank UI (a bank could never be asked). The bank API still accepts the type so an old full-bank export re-imports. Bank draws are round-robin, not pure-random: each row tracks when it was last served and selection prefers the least-recently-served match (ties broken at random), so a small pool doesn't repeat a question until every row has been served once, including across separate game sessions. **Tags are stored lowercase and matched case-insensitively**: one rule, `question_source.normalise_tags` (strip, lowercase, drop empties, dedupe), is applied by the dashboard on save, read and filter and by `question_source._parse_tags` on draw, so the reserved tags (`nsfw`, FFA's `truth`/`dare`) and any requested filter match a row however it was typed or imported. That includes the NSFW gate: a row tagged `Nsfw` is adult and is served only in a channel Discord itself age-restricts, directly or through its category (`is_age_gated_channel`); the gate must not compare a literal string, since 68 prod rows imported as `"Nsfw"` would otherwise serve in SFW channels (safety-sweep-1). Most Likely To's vote select also consults the no-contact list: a blocked voter→target pick is dropped behind the ordinary "✅ Voted" ack (`docs/specs/no_contact_spec.md`). The multi-round ones rotate through rounds: each round opens with a fresh question (from the bank or a host-supplied queue), collects votes or submissions, closes the previous round's view, then opens the next. `wyr` parses an optional `a | b` opening question; `nhie` clamps `lives` to 0–10 and disables elimination when set to 0, and declares "last one standing" only once **at least two players have ever registered and someone has been knocked out** (`find_winner`; `lives` never drops a row, so its size is the max roster; vote-games-51: a round in which exactly one member voted does not crown or pay that member); `rushmore`, `price`, and `clapback` show a live countdown timestamp the host can skip with a button. **`price`** (trivia-tail-85/86/87/94/97) opens a **join lobby** (`LOBBY_GAME_TYPES`, floor `games_price.logic.MIN_PLAYERS` = 2, `start_in` with a countdown auto-start through `PriceCog.auto_start`; a `joining` row is recovered as its lobby view): the roster is what lets a round close early: the submission view takes `expected_ids` (the ids in `payload['players']`) and skips its timer once **every joined player** has answered (`roster_all_in`). Submission stays open to the whole channel, so the rule is on ids, never a headcount: a spectator's price counts in the reveal and the vote but fills nobody's seat (three prices must not close a three-seat round with a joined player still locked out), and the board's counter reads `Submitted: **3** (2/3 who joined …)`. The embed names the host's **⏭️ Skip**. With no `source:` chosen the game runs on the bank when it holds a matching scenario and on the host otherwise (`resolve_source`); `ai` and `both` are gone from the slash choices and the schedule schema (a persisted value runs on the bank). A host- or player-written scenario is prompted by a **📝 Write Scenario** / **🎲 Draw From the Bank** row on the board itself (host/mod gated; `players` opens Write to anyone; two minutes, then the bank), never a public `<@host>` ping. Write is refused ("Someone already submitted a scenario!") only once the modal has actually resolved (a submit, or the bank drawn), never on *open*: Discord does not report a dismissed modal, so a host who closed it can press Write again (otherwise the first press would take the slot and the host would sit locked out for the whole wait, and with `host` source on an empty bank the round would then skip). The vote needs **three submitters** (`MIN_VOTERS`): two would be a forced 1-1 cross-vote and a guaranteed double tie, so a two-price round is revealed and moves on. **End Game** on the submission view (host/mod, behind the confirm) records the round's prices so far and runs the recap path, which pays everyone who submitted in any round; the recap's **🔁 Run Again** is open to any member and opens a new lobby with the presser as host through `launch_refusal`; that *is* the hand-off, so the separate **Hand Off** button (trivia-tail-97) is gone, matching Rushmore's card (social-prompt-45). `rushmore` drafts in one of two modes (slash `mode:` arg or dashboard **Draft Mode** dial; **default blitz**, social-prompt-37: a six-player snake is 24 timed turns of dead time for five people): **blitz** has everyone with an empty slot pick simultaneously each round, duplicates resolved first-come with an ephemeral "taken, try again"; the board redraws as each pick lands (todo #208/#209; before this the board only updated at the start of the next round, so a blitz pick vanished into an ephemeral "✅ Picked!" and nobody else saw it land until the round turned over). A burst of near-simultaneous picks coalesces into one edit rather than one per pick (`RedrawCoalescer`), and the round's countdown is fixed when the round opens so a mid-round redraw doesn't reset it, while **snake** pings each player on their turn, with one message per turn carrying its own **Make Your Pick** button so nobody scrolls back to the board, and the 10-second nudge *edits that same ping* rather than posting a second one. After the draft, skipped slots get a 60-second **backfill window** (own button, duplicates still blocked) before boards go final; boards that are still all-skip are hidden from the FINAL BOARDS embed and excluded from the vote. The vote card says **anyone in the channel can vote** (always true; never stated before), and a tie is broken on fewest skips, then lowest total pick time (`tally_votes(skipped=, pick_times=)`; only a dead heat after both is shared; social-prompt-36: a tie must not crown and pay every tied uid). The player floor is **3** in `clamp_player_limits` and on the dashboard: a two-player draft always ties 1–1 since nobody can vote for themselves. The recap's **🔁 Run Again** is open to any member and relaunches with the presser as host through the launch guard; that *is* the hand-off, so the old host-gated **Hand Off** button (a command hint that disabled Run Again) is gone (social-prompt-45). `clapback` pairs answers into head-to-head matchups with a special-case round-robin for 3-player games; a unanimous winner earns a "CLAPBACK!" bonus, and an odd submitter count gives one player a bye worth that round's average score; a matchup closes once every eligible player has voted (decision D1, instead of every vote running its full timer) and the host can close the write window early (full bracketing, scoring and pacing rules in [clapback_spec.md](clapback_spec.md)). Bank lookups are NSFW-gated on the channel (`channel_allows_nsfw`), so NSFW prompts only surface in age-gated channels.

**The round games' cards are Components V2, on one shared frame** (`games/utils/round_layouts.py`). The frame is what the three cannot drift on: a **round card** (`## icon Title` with a grey **❓ Help** beside it, `Round **N**` and, on a timed round, `⏱️ Auto-advances <t:…:R>` on the same line, the game's own body, the game's controls, then `-#` subtext ending in `Hosting? /games host opens your controls.`), an ephemeral **host panel** (**⏭️ Next**, **🏁 End Game**), and a **recap** (heading, the line saying why the game ended, a ` · ` facts line, the game's sections, the payout as a `-#` line). **Nothing host-only is on the round card:** Next and End Game live on the host panel, sent to the host at launch and reopened with `/games host` by whoever those controls accept (host, mod, Game Host). The panel holds no state and looks the live round up at each press, since a round game swaps in a new view every round. **The one exception is Next on a scheduled game**, which any voter may press once it unlocks (below); there it is not host-only, so it stays on the card. A round **waiting** for a prompt shows only Pose and Help; a **closed** round is the round's record and carries no controls at all, so nothing on it can be pressed. The Pose queue's size is a subtext line (`2 questions queued`), since a hosted game's card has no Next label to carry it. Every button is grey. A board still posted as an embed at restart is redrawn as a card during recovery (`redraw_embed_era_board`) rather than on its next vote, because the recovered view has nothing to answer the old Next and End Game buttons with. **Would You Rather's card** puts each option over its own bar (`🅰️ **fly**` / bar / shown voters), with 🅰️ / 🅱️ / 👀 Show My Vote in one row and ✍️ Pose Question under it; a side's shown voters are fitted by whole names (`+N more`), which the embed never was; there is no player cap and every voter may press Show My Vote. **Never Have I Ever's card** puts the statement over its 😈 / 😇 bars with 😈 Guilty and 😇 Innocent under it (grey; the red/green pair colored a choice that carries no such meaning), then **Still Standing** (heart pips, most hearts first) and **💀 Eliminated** as their own blocks, kept on the closed frame as the round's record and fitted by whole lines; names go through `games/utils/names.member_name`, so an uncached member reads `User <id>` where the embed printed a bare id. A wipe-out (everyone eliminated) posts the same recap card as a win (the guilt board and the payout line). **Most Likely To's cards**: the lobby wears the small lobby strip with grey Join / Leave and Help beside the opening text (Start is on the host panel, and takes the panel's own gate, `may_control`, so a Game Host can start as well as the host or a mod; the panel carries Start, Next and End Game together, because a panel that swapped its buttons when the game started would have to be edited from a press that may come from a different panel); the round card is the prompt over the player dropdown, with **no tally while the round is open** (votes are secret, and a count would sit at whatever it was when the card was last drawn) and `**N** votes cast` on the closed frame; the results and the standings are their own cards, the standings on the shared recap frame with the round-cap line as a builder argument rather than a description prepended after the build. Both name players through `name_fn` and a miss reads `User <id>`; the roster, results and standings are fitted by whole lines.

**Pacing and endings of the three reactive round games** (`games/utils/round_pacing.py`, shared by WYR, NHIE and MLT so the rules cannot drift; vote-games-52/53, discovery-1/3, platform-23). Each launch resolves a `(round_seconds, max_rounds)` pair: a schedule option wins (even an explicit 0), else the dashboard dial on the game's panel (`round_seconds` default 0 = host-paced, `max_rounds` default 10; 0 = no cap), clamped to 0–300 s and 0–50 rounds. The slash commands carry no pacing options (`wyr/cog.py:488` passes `None`, so the dial applies). The pair is stored in the payload with `scheduled` (the scheduler stamps `scheduled: true` on its option bag; feature rotation launches as host 0, which counts the same). Each round records `opened_at`; a timed round shows **⏱️ Next Round — Auto-advances `<t:…:R>`** and closes itself on `asyncio.wait_for` (Two Truths & a Lie's pattern) unless Next, End or `force_end_active_game` (which pokes the view's `_advanced_event`) gets there first. Next is an early skip, never removed. After a restart the timer resumes for the remainder (at least 5 s). **Next** is host / mod / the configured Game Host role (`games_editor_role`, the same role that may move other players); on a **scheduled** launch anyone who voted this round may also press it once the round has been open for the round timer or, host-paced, 90 s (`SCHEDULED_NEXT_UNLOCK_SECONDS`), with the refusal naming the unlock moment, so an absent schedule creator cannot stall round 1. The round that reaches `max_rounds`, the host's **🏁 End Game** (host / mod / Game Host, behind the usual confirm), pressing Next on a game past the 24 h line (vote-games-59: a bare guild-0 end would pay nobody and drop the round), MLT's roster falling under 2, and `/games end` all end through **one paying path per game** (`_finish_game`: `end_game(bot=, player_ids=…)` with a `reason` of `ended`, `round_cap`, `expired` or `too_few_players`) after writing the open round: WYR posts the **Game Over** card (rounds played, total votes, the most divisive question and its split; vote counts only; who voted is each voter's own to show, see below), NHIE resolves the round (guilt, hearts) and posts the **guilt board** ("Game over — here's the final guilt board"; its roster is the lives tracker plus every voter, so a `lives:0` game pays too), MLT tallies the open round, posts its results, banks the crown and posts **Final Standings**. Votes are written to the payload on every press (`persist_votes`, through `modify_payload`), not only on Next, so a restart mid-round rebuilds the tally it shows (vote-games-58). **WYR votes are anonymous by default and each voter's own to disclose** (vote-games-61): the round board's **👀 Show My Vote** (any voter, after voting; a non-voter is told to vote first) names the presser beside their pick; each side lists its shown voters and counts the rest as `+N anonymous`, and the choice rides in the round's `shown` list beside `a`/`b`, so a rebuilt view still names them. It replaces the host/mod-only **Reveal Voters**, which named the whole room and refused everyone else (five refused presses in one prod game); a mod who needs to know who voted reads the vote rows in the Anonymity Audit, which is why a self-reveal writes no `voters_revealed` row. The footer badge reads *Anonymous unless you Show My Vote* rather than a bare *Anonymous* (`payload["anonymous"]` is always `True`; there is no named-round launch option). **Every Pose queue holds 15** (`_MAX_QUEUED_QUESTIONS` / `_MAX_QUEUED_PROMPTS` / `games/nhie/logic.py` `MAX_QUEUED_STATEMENTS`, the last because NHIE's queue would otherwise be unbounded; vote-games-62); the sixteenth pose is refused with "The … queue is full (15). Let some play first!". `/games end` on these three types calls the cog's `end_with_recap` (looked up by cog name, `RECAP_ENDING_COGS` in the config cog) instead of the red Force-Closed card; an MLT lobby that never started has nothing to recap and force-closes as before.

### Anonymous-submission games

**Anonymous Truth or Dare (FFA), Hot Takes, Fantasies & Dealbreakers, Anonymous AMA** post submissions to the play channel without the author's name attached. Every such submission is recorded in `anon_audit_log` (who posted it, when, and a pointer to the message) and is reviewable on the admin dashboard's **Anonymity Audit** panel (`anon_audit_spec.md`). If an audit channel is also configured, the submission is mirrored there with the original author visible, so staff watching Discord see it without opening the dashboard. **All three member-written games say so on their own boards** (anon-tail-75): FFA's reply help, the Hot Takes lobby and the Fantasies panel each carry the line *mods can still see who sent it*, next to a how-to-play paragraph on the card itself rather than only behind the Help button.

**FFA embed mode** (`/games play ffa`; anon-tail-69/70/76) serves **truths by default**: `kind:` defaults to `truth` on the reply-button command (`EMBED_DEFAULT_KIND`) and a launch that names no kind, from the scheduler or rotation, draws a truth too, because a third of the bank's dares ask for a voice note, photo, video, nickname or status change that an anonymous text box cannot deliver; `kind:dare` / `kind:random` and the banner card (`/games play ffa_banner`, open chat, still random) draw them on request. The command's tag pre-check passes the kind into `has_matching_questions(kind=…)`, so `kind:dare tags:wren` where every wren row is a truth is refused at the command with the guard's `no_tag_match_message` rather than launching, finding nothing and blaming channel permissions. Each posted prompt's `prompts` entry records its `repliers` (`games_ffa.logic.note_reply`, de-duplicated) beside its `reply_count`, **recorded for payout only**: `ffa` is in `game_roster.ANON_ROSTER_TYPES`, so the per-reply session touch, the Close and the sweep all land the game in the games session without its roster, and `/recap` (which names session players) never lists a replier. The game finally **ends**: the host's or a mod's **🏁 Close** (on the ephemeral host panel with ⏭️ Next, `games/ffa/layouts.py`; the prompt card keeps 🎭 Reply, 🎲 New Alias and ❓ Info, rebuilds its reply-count line from the payload rather than reading the footer back, and carries no truth-blue / dare-rose color; behind the usual confirm) runs `finish_ffa_game`: every prompt message becomes its closed frame (the prompt and its count, no buttons; a prompt still an embed on screen closes as a card too), the **Anonymous Truth or Dare — Game Over** card lists replies per prompt, the 🔥 busiest prompt, total replies and the count of distinct repliers (no names, the recap is as anonymous as the replies; "no replies came in" is a one-liner instead), the prompts' `confession_emoji_assignments` / `confession_pools` rows are cleared (`confessions_service.clear_anon_identities`), and `end_game(bot=, player_ids=repliers, reason='ended')` pays. `ffa` left `game_roster.NO_ROSTER_TYPES` for this: `_ffa` rebuilds the same roster from the payload, so the 24h sweep and `/games end` pay repliers too, while a banner card (no `prompts`) yields nobody and, its launch-time `update_session` gone, never opens a games session. The alias map itself now has a clock: migration 211 adds `created_at` to `confession_emoji_assignments`, `purge_old_thread_posts` sweeps it at the same TTL as `confession_threads` (fourteen days; pre-migration rows default to 0 and go on the first sweep; a thread older than the TTL has already lost its routing row), and `purge_user_data` deletes a member's alias rows outright (`docs/data_register.md`). `hottakes` runs in two phases (submit, then a 5-step temperature vote per take with a live results bar); the public "🔥 Hot Takes voting is starting!" heads-up posted when the host opens voting names nobody: it counts the takes and is sent with mentions disabled, because the submissions are anonymous and an @-mention of every submitter would attribute a lone take outright. **Start Voting needs two takes** (`games/hottakes/logic.py` `MIN_TAKES`, anon-tail-72): one take is not anonymous (the room knows whose it is) and the refusal says so. Start Voting records the phase on the live row (`state = 'playing'`), and boot recovery branches on it: a lobby (still `joining`, no results) gets its submit view re-registered on the anchor message so the host still presses Start Voting, while a game in voting is re-driven from the first take without a persisted result. Recovery must not key on the take count alone: an empty lobby would be left with dead buttons until the sweep, and a lobby holding any take would be force-started into voting on restart (platform-29, anon-tail-66). The host panel carries a host/mod **Cancel Game** button behind the usual confirm popup; a cancelled lobby has no roster, so it archives with `reason = 'cancelled'` and pays nobody, and the lobby card becomes the cancelled notice. **Each take is paced** (anon-tail-71/74, reusing `games/utils/round_pacing.RoundPacing`): the launch resolves `round_seconds` through `resolve_pacing`: a schedule option (even 0) wins, else the **Seconds per Take** dial on the Hot Takes dashboard page (`hottakes`, one dial, no bank), else `DEFAULT_TAKE_SECONDS` (45); 0 is host-paced. A timed take shows the shared **⏱️ Next Round — Auto-advances `<t:…:R>`** field and closes itself when the clock runs out; it also closes the moment **everyone the take is waiting on has voted** (`active_voters`: every submitter plus everyone who has voted on an earlier take this game, minus the take's author; `everyone_has_voted`), and **⏭️ Next Take** (host / mod, on the host panel) is an early skip rather than the only way on. A lobby still an embed on screen at the restart that brings the conversion is redrawn as a card on recovery. Every embed prints the mode as **Unfiltered** / **Screened** (`logic.mode_label`; social-prompt-44). The sentence modal carries the turn's timeout and hands its sentence to the turn view from `on_submit`; the button callback does not await `modal.wait()`, so a dismissed box leaks nothing.

### LegitLibs

`legitlibs` runs a Mad-Libs-style template fill in one of **two** modes. **Classic** fills blanks one at a time round-robin, with a volunteer rescue path when a player times out. **Quiplash** has every player fill in parallel and reveals one filled version per player at the end. Templates are **per-guild** (`legitlibs_templates.guild_id`, migration 124): a guild draws its own templates plus the shared **global pool** (`guild_id = 0`), and an admin can promote a template to the pool, or claim it back to the server, from the dashboard (per-row *Make global* / *Make server-only*; the starter pack ships global). Templates are picked by tier (1 Flirty → 4 Unhinged, default 2) with optional tag filtering, and the picker avoids the five most-recently-used templates per guild. Each channel has a `max_tier` cap (dashboard-managed); requesting a higher tier plays at the cap, and the slash entry tells the host so ephemerally (`classic_logic.tier_clamp_note`, worked out before the defer; the modes clamp again for the headless doors but only log; trivia-tail-93). Per-blank fill prompts and example text are resolved through a fallback chain (most specific → bare part-of-speech) so even an under-specified template still renders a useful modal.

**Player range is mode-aware** (`validation.player_range`, trivia-tail-83). The dashboard derives a template's stored `player_min`/`player_max` from its blank count (each player fills 5–10 blanks) and re-derives it only when the blanks actually change, so the starter pack's authored range survives a title edit. That range is a **Classic** fact: round-robin hands out the blanks, so a 5-blank story really is a one-player Classic, and Classic's lobby enforces it. **Quiplash** has everyone fill every blank, so it ignores the stored range and takes a fixed 2–12 (`QUIPLASH_PLAYER_MIN`/`MAX`); before this, every 5–9-blank template was a one-player Quiplash lobby and nothing could seat more than five. The dashboard card and the editor show both ranges, and the list route carries `quiplash_player_min`/`max` so the panel never re-derives the constant.

Every LegitLibs card is a bare Components V2 `LayoutView` (`games/legitlibs/layouts.py`; `rendering.py` keeps only the three text renderers a template is filled with). One view class carries every phase (`views.LibsCard`: the mode hands it the card's items and a `custom_id` → callback map, and re-renders it with fresh items as the counter ticks). **The lobby** wears the small lobby strip, with grey Join / Leave and Help beside the title; the four **fill cards** (Quiplash's fill, Classic's fill, the rescue claim, the rescue fill) share one shape: title, the phase's hint, a `Heat · counter · ⏳ countdown` facts line, the redacted story or the volunteer roster, and the phase's one button, and their closed frames carry no controls. A phase that closes also disarms its host-panel Cancel (`LibsCard.close_phase`), and a Cancel confirm answered after the close cancels nothing: otherwise Cancel Round could reach a round mid-reveal and end it with no roster, so the reveal's paid close would find the row gone and pay nobody. A closed **lobby** (LegitLibs', Two Truths and a Lie's and Hot Takes' alike) carries no Help either: its view is stopped, so a Help there could only fail. **Start and Cancel Round are on the ephemeral host panel** (`/games host`), one panel for the whole round: a press out of its phase answers rather than acting, and Cancel always confirms first, on every phase. The cancel edits the phase's card into the Cancelled notice directly (editing through the confirm's own interaction, which has already been answered, would never land the notice). Quiplash's **Leave** works. **🔁 Another One** is re-sent as a row under the last card's own items (a V2 message is its view, so a row can't be attached without the card), and the presser is handed the next round's host panel. A filled story is fitted to the card's 4,000 rather than Discord's 4,096 (Quiplash never truncated at all), and the rescue roster and the contributor line are fitted by whole escaped names; a member nobody can name reads `User <id>`. A restart still ends the round.

**A round is short and loops.** Both modes give the room **two minutes** to fill (`FILL_TIMEOUT`, was five; the loop already ends early once everyone has submitted), Classic's rescue path is unchanged (45 s claim, 2 min rescue fill), and the last reveal message carries a **🔁 Another One** button (`views.RecapView`, host or mod) that draws the next template from the pool at the same tier, mode and tag through the shared launch guard, attached only after `end_game` has run, so the guard sees a free channel (trivia-tail-90). It never re-uses a template id, so the recent-use window steers it away from the story just played; when the pool is exhausted the press is answered ephemerally. **The reveal pays the people who put a word in, not everyone who pressed Join** (trivia-tail-95): Quiplash pays `quiplash_logic.payout_roster` (the complete submitters), Classic pays `distribution.unique_contributors` (whoever filled a blank, rescue included); `player_count` on the history row stays the joined roster.

### Start countdown + host nudge

Nine games open a join lobby and wait for a human to press the start button: **Clapback, Spin the Compliment, Marry-Fornicate-Kiss, Most Likely To, Mt. Rushmore Draft, Story Builder**, **Hot Takes** (*Start Voting*), **Fantasies & Dealbreakers** (*Start Round*) and **Name Your Price** (*Start*) (`LOBBY_GAME_TYPES` in `games/constants.py`; anon-tail-72, trivia-tail-85). Only these take `start_in:[1-60]`. Two more games, Two Truths & a Lie and LegitLibs, also open a lobby and wait on a host press, but were left out and take no `start_in` (see `docs/plans/game-start-countdown.md`, recoverable with `git show 678a16fa:docs/plans/game-start-countdown.md`); every remaining party game posts its first prompt the instant the command runs, so it has nothing to count down to. `start_in` stamps a `start_epoch` in the game payload and renders it as a live Discord relative timestamp in an **⏰ Starting** field on the lobby embed, refreshed on every join/leave edit. For most it is **advertising, not automation**: the game does not auto-start, and the host still presses the button. **Clapback and Name Your Price are the exceptions** (clapback-8, trivia-tail-85): see *Countdown auto-start* below.

When the advertised moment arrives, `games/start_ping_service.py` posts a nudge in the game's channel mentioning the host by name and by button (`⏰ @host — time to start **Clapback**! Hit **Start** when everyone's in.`), allow-listing only that one user. For a game whose start button lives on the host panel the nudge names the command that opens it instead (`Open `/games host` and hit **Start Draft** when everyone's in.`; `start_instruction`, which the idle-lobby nudge shares), since the button is on the host panel, not the card the nudge lands under. A **dashboard-scheduled** lobby game gets the same nudge the moment its lobby lands, aimed at whoever created the schedule; otherwise a scheduled lobby sits there with nobody aware a press is pending. Scheduled lobby-less games are never nudged; they self-run, and neither is a scheduled lobby of a game that starts itself.

**Countdown auto-start** (clapback-8). A lobby game whose cog registers a starter in `bot.lobby_auto_starters[game_type]` (`(row, payload, channel) -> bool`; Clapback and Name Your Price: `ClapbackCog.auto_start`, `PriceCog.auto_start`) is **started by the same sweep** at `start_epoch` when the roster is at or above the game's floor (`auto_start_due`: countdown reached, `lobby_roster_size >= lobby_min_players`, no earlier attempt flagged `auto_start_failed`). The starter re-reads the roster, applies the Start button's own gates (Clapback's no-contact `playable_players` floor and `MAX_PLAYERS`), stops the lobby view and retires its buttons exactly as a press would, runs the shared `_begin_game` (scoreboard seed, state → `playing`) and spawns the game loop as a background task so the sweep is never held for a game's length. The lobby embed's countdown field says so: `<t:…:R> — on its own, once 3 have joined`. Short of the floor at the moment, the host is nudged **once** with what the lobby is waiting on (`build_short_roster_nudge`: `⏰ @host — **Clapback**'s countdown is up, but only 2 of the 3 it needs have joined. It starts on its own the moment 3 are in — with fewer than that it closes after 60 minutes.`) and the idle-lobby close below runs from the advertised start as before, but the game still starts itself the tick the floor is reached after that (`auto_start_due` is deliberately not gated on `start_ping_sent`). A starter that returns False (the no-contact floor refused) falls back to the ordinary "time to start" nudge, and Start then gives the host the usual refusal line; one that raises is flagged `auto_start_failed` and never retried. A **scheduled** lobby of such a game therefore runs with nobody at the keyboard: the scheduler stamps `start_in = SCHEDULED_AUTO_START_MINUTES` (10) when the schedule's options name none, keeps a schedule's own `start_in`, and skips the creator nudge for it. Games without a starter keep the press-the-button contract above unchanged.

**Name Your Price's cards are Components V2** (`games/price/layouts.py`). The lobby wears the small lobby strip with grey Join / Leave and Help beside the title; the roster is fitted by whole names (anyone may join). **Every host-only control is on the ephemeral host panel** (`/games host`): Start, Cancel Lobby (red, the one destructive press), Write Scenario, Draw From the Bank, Skip, Add Rounds and End Game on one card for the whole game, since the game moves between phases on its own, so a panel showing only the current phase's buttons would be stale a minute after it opened; a press out of its phase answers plainly (`_HostControls`). The scenario wait (`ScenarioPromptView`, now a `LayoutView`) keeps **📝 Write Scenario** on the card only for the `players` source, where anyone may write; for the host it is on the panel, and the wait's view is registered as the game's live one for its duration so the panel reaches it and a force-close wakes it (`_done_event`). The submission board and the vote card carry their countdowns on stable-id Text Displays (`GameTimer(timer_item_id=…)`); the reveal's ladder is fitted by whole lines; the vote's dropdowns are cut to 25; the round results carry no accent color, 🎯 and 🤯 carrying the outcome, and a tie lists every winner. The cancelled-lobby and restart pick-up notices are cards. A member nobody can name reads `User <id>`. **Help sits beside the title on every card:** the AMA board, the Name Your Price submission card and the Anonymous Truth or Dare prompt card put "❓ Help" in a Section accessory like the other games, custom ids stable so a live board keeps working. **Names on every party game's cards come from `shared.name_resolver.build_name_fn`** (`games/utils/names.build_names`, built once per render or game in async code): the live member cache, then `known_users`, so a member who has left or is uncached is still named; only a true miss reads `User <id>`, as does a no-contact pair on purpose. The same holds for Name Your Price, MLT, LegitLibs, Hot Takes and Fantasies; there is no cache-only `member_name`. AMA's `build_board_layout` and NHIE's `build_round_layout` take a required `name_fn` (a default would let an un-wired caller render quietly), and `tests/contracts/test_embed_name_render_sites.py` has a row for each cog. **One host card, one set of helpers:** every game's ephemeral host panel is `round_layouts.build_host_panel_layout(icon, blurb=…, rows=[[buttons]…])`: heading, blurb, the `/games host` pointer, then the buttons the game passes, `round_layouts.red` for its one destructive press, (`tests/games/test_games_host_panel_layout.py` pins each game's panel). Rushmore's panel is a `host_panel.GameHostPanel` like the rest, its Start Draft handed to whichever of the lobby, draft or vote view is live (the latter two answer "the draft is under way"). `round_layouts.grey` / `line` / `fit_lines` are the shared helpers the game layouts use. **Phase edge cases:** a Name Your Price host-panel End Game / Add Rounds pressed while a scenario is being written, or End Game during the vote, answers in its own words (`SCENARIO_WAIT_*`, `VOTE_END_REPLY`) rather than the lobby's "hasn't started yet", and End Game during the few seconds of reveal says the round is over instead of showing a confirm that `end_early` would silently drop. Rushmore's vote view closes with a flag before the tally and only `stop()`s after the winner card replaces the dropdown, so a late select press is answered ("The vote is over.") rather than failing. AMA's `refresh_status` re-registers the board with `bot.add_view` when its edit fails, because the rebuild had already replaced the buttons discord.py's view store holds.

**The Game Lobby ping** (discovery-2 / clapback-11, decision D4). A member launch posts nothing but the board, so a lobby would be invisible outside its channel. The same sweep posts **one** line per lobby, the first tick it sees the lobby's board (`message_id` written; every DB-backed launcher does that before returning), mentioning the guild's opt-in **Game Lobbies** role: `<@&role> 🎮 A **Clapback** lobby just opened — it starts <t:…:R>! Jump in: <jump link>`, as message `content=` with `AllowedMentions(roles=[role])` and embeds suppressed, never inside an embed. Platform-level on purpose: every `/games play` launch of a lobby game and every scheduled one gets it with no per-cog edit; lobby-less games (which post their first prompt at once) are out of scope. The role is `feature_roles.GAME_LOBBY_PING` (config key `game_lobby_ping_role_id`, the **Game Lobby Ping Role** dial on **Games → Global Config**, `GET/PUT /api/games/config/lobby`), provisioned on first use through `ensure_config_role` like every other ping role: never touched ⇒ `@Game Lobbies` is created on the next lobby; a stored "(none)" ⇒ opted out and the sweep stays silent (`resolve_game_lobby_role` returns `(True, None)`; an unreachable guild returns `(False, None)` and the lobby is looked at again next tick rather than flagged). Members pick the role up through Discord Onboarding (`opt_in=True`, so the Onboarding page offers it). `game_lobby_pinged` in the payload is the once-only flag, and both senders take it as a **claim** (`claim_game_lobby_ping`, an UPDATE that matches only while the flag is unset) *before* they send: a schedule with **Announce When It Starts** ticked claims it before its own announcement, so its line (with whatever role it names) stands in for the sweep's. The claim, not the write, is what makes the ping once-only: the two run on separate clocks and were both able to fire for one opening, the sweep reading a row at the top of its tick that the schedule flagged moments later; whichever loses the claim stays silent. A launcher that keeps its round in memory and registers no row (risky_roll) has nothing to claim, and announces (`no_row_wins`). The ping is recorded through `record_game_start_ping` in `ping_tracker/service.py` against the lobby it advertised, so the Ping Response report can count who joined. Per-launch suppression (a `ping:false`-style option) was **not** built: nothing cheap exists at the platform level, and it would need a parameter on six slash commands. **Formerly named "Game Night"** (todo 190): the key was `game_night_ping_role_id`, the flag `game_night_pinged`, the role `@Game Night`. Migration 225 renamed the stored config row, the `bot_managed_roles` row and the payload flag (live and history) rather than leaving them behind; a guild's "(none)" left under the old key would read as never set under the new one and turn the ping back on with a freshly created role. The Discord role the bot already made keeps its old name until an admin renames it.

A schedule row with **Announce When It Starts** ticked adds one more message, and the order is **board → announcement → nudge**. The announcement fires *after* the launcher returns, not before it, because it carries a jump link to the board and there is no board to link at until the launcher has posted one (todo #97); landing people in the channel to hunt for the game was the complaint. Every DB-backed launcher writes `message_id` before returning, so `get_active_game_by_id` reads it straight back; `risky_roll` keeps its round in memory and registers no row, so it announces the bare line with no link rather than a URL with a missing segment. The ordering also means a launch that fails announces **nothing**: the old order pinged a role about a game that then never appeared. That leans on `launch` returning `None` for *every* failure, which is a contract worth stating: `wyr` and `nhie` run their first round inside `launch`, and an empty question bank posts its notice, calls `end_game` and unwinds **normally**, so both check that their `games_active_games` row survived the round and return `None` when it didn't (`tests/contracts/test_games_launch_contract.py`). Without that they reported `launched` for a game that had already ended, putting the ping directly under the "bank is empty" notice. The configured role is allow-listed explicitly (`AllowedMentions(roles=[Object(id=…)])`, `none()` when unset), and the send suppresses embeds so the link doesn't render a preview of a board one message above it.

The nudge is driven by a 15-second poll over open lobbies rather than a per-lobby timer, so it survives a restart: a bot that was down across the start time nudges late on its next sweep instead of never. A game started early, cancelled, or timed out leaves the `joining` state and drops out of the sweep, so a running game never gets a "time to start". Each lobby is nudged at most once (`start_ping_sent`), and a lobby whose channel has become unreachable is marked rather than retried every tick.

**Idle lobbies** (discovery-6). The same sweep applies two per-guild dials from **Games → Global Config → Idle Lobbies** (`config` keys `games_lobby_idle_nudge_minutes`, default 20, and `games_lobby_idle_cancel_minutes`, default 60; 0 switches a step off; `GET/PUT /api/games/config/lobby`). A `joining` lobby opened **without** a countdown is nudged once after the first window, the same tap on the shoulder a countdown lobby gets at its advertised start, naming the button and, when the close is on, the deadline (`⏰ @host — **Story Builder** has been waiting 20 minutes. Hit **Start Story** when everyone's in — with fewer than 2 players joined it closes on its own after 60 minutes.`). After the second window a `joining` lobby that still holds **fewer than its game's minimum roster** (`LOBBY_MIN_PLAYERS` in `games/constants.py`, mirrored from the cogs' own floors, with a test pinning them, or the higher floor an mlt / rushmore payload names) is closed through `end_game(reason='lobby_timeout')` with **no payout** and its lobby message is retired (`⌛ **Lobby timed out** — …`, components removed, the in-memory view stopped). A Components V2 lobby cannot take a `content=` line, so a V2 view with a `retire(anchor, notice)` method (Clapback's) redraws its own card with the notice above greyed-out buttons, and any other V2 lobby message is replaced by a card holding just the notice. A countdown lobby's hour starts at its advertised start rather than at open; a lobby with enough players to start is **never** closed by the sweep; that is the host's call, however long they sit on it. Before this, only Clapback's own 10-minute view timeout closed anything; the other five lobby games and every lobby that survived a restart sat until the 24-hour sweep. This is a pre-game close of a lobby that never filled, not a mid-game inactivity timeout (see Non-goals).

**Live game boards.** A live board buried under chat is easy to lose track of: nothing re-surfaces it today except a full redraw. The **Live Game Boards** dial on **Games → Global Config** (`config` key `games_board_sticky_enabled`, default **off**, `GET/PUT /api/games/config/board-sticky`) is a single per-guild knob covering every game that wires itself to it: one dial, never a per-game override. Eleven games have, across thirteen board sites, and they split into three shapes. Two hand the board an existing message, which then *moves*: **Mt. Rushmore Draft**'s draft board, sticky for the length of the draft, and **Name Your Price**'s submission board, sticky for each round's submission window. Eight more post a **fresh** board per round and leave the one that just closed on screen as that round's record: **Never Have I Ever**, **Would You Rather** and **Most Likely To** (the in-play round board; the lobby is not on the dial), **Hot Takes** (each take's vote board, not the submission phase) **Fantasies & Dealbreakers** (two sites: the submissions card while its window is open, then one board per entry being voted on), **Two Truths and a Lie** (the subject's board being guessed on), **Story Builder** (the turn card, for as long as that writer's turn is open) and **Clapback** (two sites in sequence inside every round: the prompt card while answers are open, then one card per matchup being voted on). **Truth or Dare** is the third shape, and the only board on the dial that is sticky for just *part* of its life: the room is one message that lives as long as the room, and it follows the channel bottom from launch until the **first question is asked**, then settles where it is and stays there. From that point the question cards are the thread of the game, and a board still jumping past them would bury them one at a time, so the first question **unsticks** the board rather than retiring it (`unstick_game_board` / `LiveBoards.unstick`: the panel is released and `_panel` cleared, but `_board_retired` is deliberately left unset, so every later preference toggle and every later question still redraws that board, wherever the last repost left it). The transition is read inside the same locked read-modify-write that writes it: `asked` going from empty to one entry, in `AskQuestionModal.on_submit`, so it fires once. The same press posts the **bottom bar** described above, which is not on this dial and takes over following the chat from there. Closing the room is then the ordinary retire. Off is truly inert *for the board*: the dial is read exactly once, the moment a board is first posted, and a dial-off game draws it with no `StickyPanel` ever constructed (an in-place edit of the previous message where it has one, a plain send where it posts fresh). Two things about the adoption are **unconditional** and visible with the dial off. Story Builder's turn mention and Clapback's round-start line moved off their cards into messages of their own so a repost cannot re-ping, kept on both sides of the dial deliberately, because a card that is repost-safe only when a knob is on is a card whose second code path nobody exercises, and with the dial off the split reads as an ordinary two-message turn. And **the bottom bars are not on this dial at all**: Anonymous AMA's, and Truth or Dare's opt-in strip; the paragraph below says why, and both move with the dial off exactly as they do with it on. A mid-game flip never touches a board already running; only the next one sees the new value. A **restart** deliberately leaves the round in progress un-stuck: recovery re-registers the view against the message that is already there, and the board starts following the channel bottom again from the next round.

The wiring lives in `games/board_sticky_service.py`, not in the cogs: `board_sticky_enabled`, `board_location`/`set_board_location` (the synchronous id hooks), `build_board_content`, `make_board_panel`, `open_game_board`, `redraw_board`, `retire_game_board` and, for a board that comes off the dial while the game plays on, `unstick_game_board`. The first two cogs went through a hand-rolled copy of all of it first and the two copies were identical apart from the view's type name, which is what moved it into the service. An adopting cog now holds one **`LiveBoards`** (`bot`, `db`, a log label) instead of its own `game_id -> StickyPanel` dict, and forwards `on_message`, `on_guild_channel_delete` and `cog_unload` into it in two lines each; composition rather than a mixin, because `@commands.Cog.listener` is collected off the cog class and the listeners have to be declared there either way. Adopting is then a view plus an `open`/`retire` pair per board site. The view contract is the `LiveBoardView` protocol: `game_id`, `guild`, `_build_embed()`, plus the `_panel` and `_board_retired` attributes the wiring sets. Since Components V2 wave 3b (games core) the service also accepts the `LiveBoardLayoutView` protocol: `game_id`, `guild`, `_rebuild()` rebuilding the view's own items in place, same `_panel`/`_board_retired`, and branches on `isinstance(view, discord.ui.LayoutView)` at every site that calls `_build_embed()`; `games/bottom_bar_service.py` and `games/utils/live_bar`/`timer` carry the matching layout-shaped siblings (`PanelContent.layout=`, `schedule_update_layout`, `GameTimer._install_item`). **Deliberate deviation:** most adopters have not moved off `LiveBoardView`/`_build_embed()` yet; **Story Builder**'s turn card is the first to (Components V2 wave 3b, games), so both arms stay live side by side until every games group is converted; the embed arm retires when the last one lands.

Every mid-board redraw goes through **`redraw_board`**, never a captured message: with the dial on, the message a vote click came from may have been re-posted somewhere else since, so the redraw asks the panel where the board is (and reposts it if it has gone missing). Where a redraw was already rate-limited it keeps that gate: `LiveBarUpdater.schedule_render` is the same 3-second claim as `schedule_update`, with the edit handed back to the caller. A redraw that lands after the board retired swallows the refusal below rather than propagating it into a vote handler.

A sticky board must also carry **nothing that re-fires on a re-post**. Story Builder's turn message was one message carrying the writer's mention in `content=` *and* the card with its buttons; a repost would have pinged that writer again every time chat buried the card, so the mention was split into its own message (Spin the Compliment's shape) and the card holds only the embed and the buttons. Both are deleted when the turn is spent, the card via retire's return value. Two Truths and a Lie needed the mirror of that: its render took the subject's display name as an argument, and `build` has no interaction in hand, so the name is resolved once when the round's view is built and its `_rebuild()` reads it off the view. Clapback needed both halves at once: its round-starting mention (and the line naming whoever is sitting the round out) moved off the prompt card into its own message, and the counters its submit and vote loops advanced by editing the live embed's fields in place now live on the view, which the loops set before each `redraw_board`. Truth or Dare needed a third thing again: its room message is the **lobby card** until the first press turns it into the board, and the two differ only in their facts (the working board adds the questions-asked count), so the view remembers which of them it is showing (`_lobby_card`) and a repost before anyone has joined puts the joining instructions back instead of a board of zeroes. Its host name, the players' names, the payload and the accent were all resolved from the interaction at render time; they are now cached on the view by the one path that already had to redraw the board, which is what makes `_build_embed()` synchronous.

All of them reuse `core/sticky.StickyPanel` (never a parallel implementation) with **one instance per live board**, keyed by `game_id`: a guild can run several games in different channels at once, so a single shared panel would collide. Keying by `game_id` also means a cog with two sequential board sites (Fantasies' submissions card, then its entries) has to retire the earlier board before opening the next, or the dict overwrite orphans a live panel. `load_ids`/`save_ids` read and write the game's own row in `games_active_games` (`channel_id`/`message_id`, the same columns `update_game_message` and the busy-check's jump link use, so a repost can never drift out of step with what `/games end` sees); they are synchronous because `StickyPanel` calls its id hooks off-thread, which is why they live in the service rather than in `game_manager` alongside that table's async accessors.

Two exceptions to that, both load-bearing. First, `place()` removes whatever `load_ids` names, so a board that is **posted fresh** must start naming nothing: `make_board_panel(replaces_prior_board=False)` (derived from whether a caller handed `open_game_board` a message) returns `(0, 0)` until this panel's own first placement, after which the row names *this* board and reading it is right again (`StickyPanel` re-consults `load_ids` on every placement, not only the first). Without it, ticking the dial on would have silently deleted the round that just closed, which is that round's only record. Second, two adopters' rows name something that is not a board, so their ids live in an in-memory `TransientBoardLocation` instead (`LiveBoards(..., tracked=False)`) and their game row is left untouched dial-on and dial-off alike. **Fantasies & Dealbreakers**' row names the host's *control panel*: `recover_game` re-registers `FantasiesMainView` against whatever id is in there. **Story Builder**'s names the *lobby* message, and its turn card is deleted the moment the turn is spent, so recording it would point the busy-check's jump link and `/games end` at a message that no longer exists. In-memory is all the lifetime either needs: both are abandoned at a restart.

Two lifecycle rules are load-bearing, and both are needed; the first alone is not enough. `build` **raises** `RuntimeError` rather than returning `None` once a board is retired: `StickyPanel._place_locked` does not check its build result, so `None` would explode inside core (`EconomyCog._build_auction_panel` is the established idiom). The flag it checks is `_board_retired`, deliberately distinct from each game's pre-existing `_closed`, which is set one render *earlier* for the legitimate "complete" frame that must still go through. And `retire_game_board` calls **`forget()`** as well as `cancel_all()`, mirroring `auction_views._release_panel`: an `on_message` already in flight when the game ends can otherwise still read the panel's cached ids and schedule a restick nothing cancels, reaching the refusal above, which core logs as an ERROR traceback for a perfectly ordinary game ending. Because the callers' redraw seams can also race teardown, they swallow that refusal rather than let it escape.

Nothing is posted outside `place()`, so the old message is never deleted explicitly: `board_location` reads it straight out of the game row, `place()` treats it as "the old panel" and removes it **after** the new board is safely up. Deleting first would invert post-before-delete: a placement failure would leave the game with neither the old message nor a board.

Teardown is called at every point a board's life ends: for Rushmore a `try/finally` around both draft loops (so natural completion and a forced `/games end` alike) plus a guard for a failure that never reaches a loop; for Price the disabled frame, a host's own End Game button, and a forced end, which is idempotent since the round loop and `end_early` can both reach it; for Truth or Dare `_do_close`, which every close reaches (End Game, `/games end`, and the quiet-window idle close). Two paths cannot reach the view at all, and `LiveBoards.abandon(game_id)` covers them: a crash inside a phase unwinds past that phase's own retire (Clapback's `_cleanup`, reached through `_cancel_game`), and a transient failure re-drives a round that has already posted its boards (`_survive_hiccup`), which would otherwise leave the failed attempt's panels reposting alongside the replay's. Every round/take/entry close **retires before it paints the closing frame**, and paints it on retire's return value rather than on the message it opened the board with: `retire_game_board` hands back wherever the board actually ended up, since a repost may have moved it since (a stale local reference is an edit against something already deleted), and retiring second would let a restick land on top of the frame that was meant to be final. `on_message`/`on_guild_channel_delete` are forwarded from cog-level listeners to every live board's panel, and `cog_unload` calls `cancel_all()` on each before clearing.

**AMA's bottom bar runs on the same machinery and is deliberately *not* on the dial** (todo #202). The bar (one line of text under **Ask a Question** / **Volunteer** / the notify toggle) follows the bottom of an AMA's channel. It is a `StickyPanel`, one per live AMA keyed by `game_id` (`games/ama/bottom_bar_service.py`: `bar_location`/`set_bar_location`, `build_bar_content`, `make_bar_panel`; the game-agnostic two thirds live in `games/bottom_bar_service.py`, shared with Truth or Dare's opt-in strip, leaving AMA's module owning its payload key and its one line of text), and because the bar is *always* sticky there is no behavior for `games_board_sticky_enabled` to switch; the dial says nothing about it. That is a deliberate anomaly, so it ships with the test that fails if it is reverted: `tests/games/test_games_ama_bottom_bar.py::test_the_bar_still_follows_the_chat_with_live_game_boards_off` turns the dial off for the guild, asserts it really is off, and then asserts the bar is placed and still reschedules itself when a message lands on top of it. AMA's own game card stays where it was posted; only the bar moves. The ids are `channel_id` off the game row, `bottom_message_id` out of the payload, and the write is a single `json_set` against that row rather than a read-modify-write, so a concurrent payload write (`modify_payload`, `_set_hot_seat`) cannot clobber the rest of the blob; the residual race is self-healing, because a stale bar id only makes the next placement's delete a 404. Like every other adopter it gets the trailing-edge 6 s debounce, post-before-delete, the five-failure ceiling and membership of the shared placement registry, so a bar and a live board in the same channel do not chase each other. `restick_on_bot=True` is deliberate: in an AMA it is the bot's own question cards and rotation announcements that bury the bar, and stopping the bar chasing its own repost is the placer's job. `PanelContent` has an optional `content` field (a panel needs an embed, `content`, or both) so the bar is not boxed in an embed. `recover_game` re-registers the panel from the persisted id **without fetching the message**, so a bar deleted while the bot was down is re-posted at the next placement rather than leaving the AMA with a bar that never moves again; and the ending takes the bar down through `unpost()`; core's `_delete_old` already retries over ~40 s, and a message it still cannot delete is one the bot could not have edited either.

### Scheduled launches

Schedules (`games_scheduled`, the Games → Scheduling panel, `/api/games/schedule`) are polled every 60 s by `scheduled_games_service`. A due row is checked in order: lateness, channel reachable, enabled dial (against the base type for a display variant), the feature rotation's hidden state, and **channel busy**. A busy channel makes the row **stay due and retry every poll** (a one-time row until its `giveup_at`, a recurring row until the slot is `GIVEUP_GRACE_SECONDS` (2 h) old), and the retry is recorded as a run (`last_run_at`, `last_status = skipped_active`). When the grace runs out a one-time row is marked `skipped_giveup`; a recurring row rolls to its next slot as `skipped_active` when a retry happened *within* that slot, else `skipped_late` (the bot slept through it). A recurring row must not roll the moment the channel is busy, or a member-opened round overlapping the slot by a minute would cost the whole day (prod's daily Risky Rolls was skipped for a round that closed 21 minutes later, platform-24). A successful launch stamps `last_launched_at` (migration 205), the one column that says when a schedule last *produced* a game; the panel shows it ("Last launched: …" / "Never launched yet") and, while a slot is retrying, "⏳ Channel busy — retrying until …". Every write the loop makes before a launch is conditional on the row still being `active` with the `next_run_at` the poll read, and the pre-launch claim must win before anything is posted: a pause, edit or delete saved on the dashboard while a poll is mid-flight wins, rather than being overwritten and launched over. **A one-time row whose launch never happened gets its slot back.** That pre-launch claim runs before the launcher is awaited, so a crash cannot double-fire, but on a `once` row the same write consumes the booking for good (`status = 'done'`, `next_run_at = NULL`), and a launcher that raised or returned None silently cancelled the member's one scheduled game. The two failure paths now restore `active` and the `next_run_at` the poll read, conditionally on the row still sitting on that claim (so a dashboard edit made mid-launch is not resurrected), and the 60 s poll retries until `giveup_at` exactly as a busy channel does. A **recurring** row deliberately keeps rolling forward to its next slot instead; the moment it was booked for has passed, and the next one is already on the clock.

The panel tags every schedulable game with how it runs (`hosting_kind` in `games/constants.py`, served on `/api/games/schedule/options` and each row): **Self-running** (`SELF_RUNNING_GAME_TYPES`: ffa, ffa_banner, risky_roll, photo; posted and finished with nobody at the keyboard), **Self-running with a round timer** (`TIMER_RUNNING_GAME_TYPES`: wyr, nhie; self-advance and end at the round cap only when a round timer is set; host-paced they show one question and wait), **Starts itself after a countdown** (`AUTO_START_LOBBY_TYPES`: clapback, price; the lobby games whose cog registers a `lobby_auto_starters` entry; a scheduled row stamps a 10-minute countdown and the start-ping sweep starts the game when its floor has joined (three, or two for Name Your Price; see *Countdown auto-start*); the schedule creator is still nudged when the lobby lands, in case the room is thin), or **Needs a host** (everything else: a lobby or host-driven round; the schedule creator is nudged when the lobby lands). Picking a game shows the matching hint under the form. The self-running and timer sets are disjoint from `LOBBY_GAME_TYPES`, and the countdown set is a subset of it, by test (discovery-4: a self-starting Clapback must not wear *Needs a host*).

**Scheduled launches are not gated by the channel allowlist**, and the panel says so under the channel picker: the list governs games members start themselves with `/games play`; a schedule (and a feature-rotation room) posts wherever it was pointed. Decision (platform-31): prod's own daily Risky Rolls schedule posts into a channel that is not on the list, so gating at create time would refuse it; the copy on Global Config and the scheduler says so instead.

### Meta surfaces

`/recap` reads the current channel's session window (the past 30 minutes of games) and renders highlights based on each game's final payload: most divisive WYR question, guiltiest NHIE player, best TTL liar, hottest hot take, and so on. The window is kept open by play, not only by starts and ends: every payload write (`modify_payload`: a vote, a pose, a join, an advance) touches the channel's session (`touch_session`, at most once per game per 30 s), moving `last_game_at` forward and merging the roster rebuilt from the payload, so a member typing `/recap` forty minutes into an AMA sees the session rather than "No active session found" (platform-22), and a joiner is in the recap from the moment they join. Ending a game merges its roster too: a paying end through `_fire_session_join`, a bare end through `update_session` directly, so the start-time call's host-only roster is completed by the end of the game. Games with no joined roster (`NO_ROSTER_TYPES`: the daily Photo Challenge post, ffa cards) never open or extend a session; `update_session` answers `None` for them, so a bot post is not a games session. Anonymous-submission games (`ANON_ROSTER_TYPES`: FFA) keep the host-only session their launch opened but their roster is paid and never merged, not by the touch, the paying end or the bare end. A lobby the idle sweep cancels (`reason = 'lobby_timeout'`) opens no session either: its join list is not a game the room played. `/games help` opens the grouped game picker described under *Meta & admin commands*. `/support` (top-level and bot-wide, not under `/games`) posts a static support-server invite; there is no `/games support`.

### Close & archive

Every game's Close/End path opens a confirm popup ("Are you sure you want to end this game?" → Yes/No), skipped when a mod passes `force:true`. On confirm (or on a mod's `force:true`): the view disables, the game's final payload is copied into the history archive, and the live-game row is freed. `/games end`, by its host or (with `force:true`) a mod, runs this teardown; AMA runs its extra view/message cleanup first so nothing is orphaned. A 24-hour sweep (`games/utils/expiry_service.py`) closes orphans: hourly, and once more at the end of boot recovery (`recovery.recover_active_games`), so a game that expired while the bot was down is archived immediately rather than keeping dead buttons and a "busy" channel for up to an hour (platform-30). Boot recovery hands every other live row to its cog's `recover_game`, and the lobby games **branch on `state`**: a `joining` row gets its lobby view re-registered on the anchor message (Rushmore, MLT, Story, Hot Takes, Clapback, Name Your Price and Two Truths; Two Truths' Start Guessing now writes `state = 'guessing'` so recovery can tell a lobby from a game in progress, and Clapback's recovered lobby is bound as a persistent view so it has no inactivity timeout of its own), while a row past its start is re-driven or ended gracefully as each game documents. Until then a Clapback lobby was re-driven as a game: an empty roster played five no-op rounds to a 'Winner: Nobody' recap, a joined one crashed at the first vote (clapback-3), and a Two Truths lobby holding any submission was force-started into guessing past the host's 2-submission floor (vote-games-56). When the sweep closes a game that **paid**, it posts one line in the channel, `📦 Truth or Dare archived after 24h — 45 coins paid to 3 players.`, with mentions suppressed; nothing is posted for an empty lobby, a bot post, or a guild whose economy is off, and a channel the bot can no longer post in is skipped without affecting the archive or the payout (platform-21, decision D2). It is a notice, not a recap, and there is **no inactivity close** behind it; see Non-goals.

**Which end paths pay: all of them.** The economy faucet fires when `end_game` is given `bot=` and `player_ids=`. A game's own completion site builds that roster from locals it has in hand; the two paths that end a game from *outside* it have no such locals, so they rebuild the roster from the stored payload via `games/utils/game_roster.py` (`roster_from_payload`, one extractor per game type, each mirroring its cog's completion site).

- The **24-hour sweep** (`expiry_service.py`) pays. Hosts routinely never press End (all 18 Truth or Dare games in the history ended this way), so a sweep that paid nobody would leave them unpaid. A game whose live view exposes `close_now` (AMA) is closed through it first, so its recap posts and pays the way the feature rotation already ended it (social-prompt-33); if that close raises, the game falls through to the archive-and-pay path.
- **`/games end`** (host confirm or mod `force:true`, `force_end_active_game`) pays. This is the normal close method for several games, not only an abort, so it credits the room the same way.

A game type with no joined roster (ffa banner posts, Photo Challenge) resolves to an empty roster and pays nobody, which is correct: they are posts, not games players sign into (Photo Challenge is paid by the economy's own `photo_post` trigger instead). An abandoned lobby lands on that same empty roster, which is the whole anti-farm gate: aborting a game that never got going costs nothing, and leaving one open all day earns what it played. A malformed payload costs its own game a roster, never the sweep it was found in.

Because every path now routes through `end_game`, its `DELETE`-first claim is what keeps a game from paying twice when a sweep, a force-end, and a host pressing End race each other.

**What `end_game` records is not gated on the caller knowing the roster.** A bare call (a lobby timeout, an empty-bank unwind, crash cleanup) archives the game's **stored** payload when none is passed, and when it names neither `player_ids` nor a `player_count`, the roster and round count are rebuilt from that payload through `game_roster` and recorded (platform-20: half the game types wrote `player_count = 0` and `payload = {}` on every non-completion path, and Play Statistics, `/recap` and the Ping Response report all read those zeros). Recording never pays: the faucet still fires only on an explicit `player_ids`. The archived `guild_id` is copied from the live row (platform-19: every bare call wrote 0, 51 prod rows invisible to the guild-filtered dashboard, thirty of them the daily photo post) and re-derived only when the row still says 0, from the bot's channel cache when a bot is passed, else from the channel allowlist. An optional `reason` (`'lobby_timeout'`, `'crash'`, `'expired'`; the sweep passes the last) lands in the archived payload so the dashboard can tell an abandoned lobby from a game that was played (clapback-9). Clapback's two lobby-death paths use it: the lobby view's inactivity timeout and a crash inside Start both go through `_cancel_game`, which reads the stored payload and archives the roster count, the rounds played and the reason: a lobby that died with six joined and no host reads as exactly that. `end_game` returns a `GameEnd` (guild, counts, `coins_paid`) or `None` when another call already claimed the game; `pay_game_rewards` returns the coins it credited to make that possible. The Ping Response report treats a photo history row at `player_count = 0` as unknown (blank) rather than a failed ping, since the daily post archives before anyone replies (photo-external-104).

**A transient Discord failure must not archive a game.** discord.py
retries `{500, 502, 504, 524}` unconditionally but **not 503**
(`discord/http.py:765`), so a 503 comes straight out of `channel.send` with no
attempt at all. `games/utils/send_retry.py` holds the two halves of the answer:
`retry_transient(op)`: three attempts, 1s then 2s apart, retrying a 5xx or a
dead connection and re-raising anything under 500 at once (a 403 will not come
good on the second try, and sleeping on it parks a game loop), and
`is_transient(exc)`, the same classification a crash handler asks afterwards, so
the two never keep drifting lists of status codes. Every Clapback phase card and
every Hot Takes take card goes out through it.

What survives the ladder is then **classified rather than blanket-archived**.
Clapback's `_play` waits 60s and re-drives itself once off its round
checkpoints, then leaves the game frozen-but-whole (`clapback_spec.md` §5.1);
Hot Takes' Start Voting leaves the row for `recover_game` without an in-process
re-drive, since a button callback is not a loop it can re-enter. Either way the
live-game row survives, which is the point: the row is what `recover_game`
resumes from, what `/games end` archives and *pays*, and what the 24h sweep
archives and pays. A non-transient error still archives with `reason="crash"`;
a genuinely broken game must not become an immortal row.

This was not theoretical. Clapback game `959cd749` was four rounds into five
with four players when the next matchup's send returned 503; the blanket
`except Exception` called `end_game`, deleting the row `recover_game` would
have picked up and skipping the `bot=`/`player_ids=` that pay a roster. Four
played rounds paid nothing. Hot Takes carried a worse version of the same
handler: a bare `end_game(db, game_id)` with no payload, no bot and no roster.
The trade taken knowingly: a retried send can post a card twice if Discord
accepted the first attempt and lost the response.

## Coin wagers (duel + group games)

All six duel/group games (Pressure Cooker, Quickdraw, Hot Potato, Hot Potato
Group, Chicken, Musical Chairs) accept an optional `wager:` amount on their
challenge/start command: equal ante from every player, winner takes the pot
minus an **optional house rake** (`wager_rake_pct`, default 0, ships dark;
when priced, the cut is named on the payout announcement so the arithmetic
visibly adds up; refunds and single-stake pots are never raked). Escrow lives
in `econ_game_wagers` (economy side, migration 094)
and settles through the shared terminal-state seam; see
`docs/specs/economy_spec.md` §6 and `docs/plans/economy-sinks-round-2.md` stage 4b
(recoverable with `git show 678a16fa:docs/plans/economy-sinks-round-2.md`).
The rule that inverts this module's usual one: `pay_game_rewards` swallows
every error because economy must never block game flow, but an escrow
**debit** raises and refuses the join/accept, so you cannot enter a wagered
game you can't pay for.

A wager replaces the nickname stake: a wagered game with no custom `stakes:`
text records "Coins on the line — winner takes the pot." as its stakes and
resolves announce-only, with no rename button and no nickname preflight. The rename
flow only runs when neither `stakes:` nor `wager:` is given (the default
"name" stake); see `docs/specs/dk_pvp_games_suite_spec.md` §4.

## Economy integration

Games are wired into the economy quest system. Quest-relevant actions call `fire_member_trigger` (`bot_modules.economy.game_rewards`) to credit a member's economy quest progress; for example AMA credits an `ama_ask` trigger when a question actually becomes visible (on submit in unfiltered mode, on host approval in screened mode; rejected questions never pay). Photo Challenge payout is handled by the economy directly (`EconomyCog._on_photo_post`): a member's image post in the configured photo channel pays the `photo_post` quest on the post itself (no reactions needed); the card itself just sets the prompt. Several other game cogs (`ffa`, `clapback`, `mlt`, `price`, `rushmore`, `traditional`, `nhie`, `wyr`) import the same game-rewards path. Credit is best-effort: an economy failure never unwinds a game.

## Permissions

**Bot needs:** Send Messages, Embed Links, Read Message History, Attach Files (Photo Challenge and card renders), Use External Emojis, Manage Messages (AMA and Story Builder tidy up their own turn messages). The bot does **not** need Manage Nicknames; that's a Pressure Cooker requirement only.

**User needs:**
- Everyone can run every game command, subject to the channel allowlist and per-guild enable flag.
- Ending a game (`/games end`) is allowed for the game's host, or a Mod/Admin (who can also pass `force:true` to skip the confirm). `/games config game-status` requires Mod/Admin (Manage Server or Administrator). On the three reactive round games (WYR, NHIE, MLT) **Next** and the board's **🏁 End Game** are also open to holders of the configured Game Host role, and Next to any voter on a scheduled launch once the round has been open long enough (see "Pacing and endings").
- `/games join`/`/games leave` are self-service; adding or removing *another* player requires the host, a Mod/Admin, or the configured Game-Host role.
- External tracking (web) requires Mod.
- Dashboard config writes need `mod`; dashboard content authoring needs Administrator OR the configured editor role.

## Non-goals

- **No cross-channel state.** Each channel runs one game at a time; the session window is also per-channel.
- **No cross-guild or in-app leaderboards yet.** History and external-game messages are collected per guild, but no leaderboard surface is rendered.
- **No per-user game settings.** Configuration is per-guild or per-channel only.
- **No pre-game RSVP.** Players join by clicking a button on the live embed.
- **No mid-game inactivity timeouts** except AMA's per-question lifecycle, the lobby idle close (a `joining` lobby that has sat for the configured hour with fewer players than its game can start with; the Clapback lobby's own 10-minute view timeout was the model; see "Start countdown + host nudge"), and the 24-hour orphan sweep. The round timer on WYR/NHIE/MLT is *pacing* the host or an admin opts into (a round closes on a clock and the next opens), not an idle close; a host-paced game still waits for a press. The host is trusted to close the game; the sweep is the safety net. Decision D2 (games deep review): the sweep's one-line "archived, N coins paid" notice is the fix for a payout that arrived a day later out of sight, and End buttons on the reactive boards are a defect fix; neither is an inactivity close, and platform-21's proposed idle-close was declined. **Truth or Dare (traditional) is the one named exception** (trivia-tail-84): opting in and play are a single `joining` board, so the lobby idle close could never tell an empty room from a game in progress, and 18 of 19 prod games were left to the sweep; its per-game dial (`idle_minutes`, default 60, because 20 closed rooms that were only between questions; 0 = off) ends a quiet room through the same recap-and-pay path as its End Game.
- **No matchmaking.** Pairings are random, with no skill or history awareness.
- **No persistent seasons.** History is raw rows only.
- **No voice, music, or TTS integration.** Games are text + embed only.
- **Pressure Cooker and Risky Rolls are not part of this suite.** They share the game registry for naming/icons but have their own entry points and infrastructure; Pressure Cooker is documented in [[pressure-cooker-spec]].

> **Note:** economy is not a non-goal: games credit economy quest triggers and Photo Challenge registers reply-cards. See **Economy integration**.

Minutes before a countdown-less lobby's host is tagged, and minutes before a lobby still short of its game's minimum roster is closed without pay; 0 turns a step off. Read per guild by the start-ping sweep (`read_idle_dials`), legacy `guild_id = 0` row as the fallback |
| Game Lobby ping role (`game_lobby_ping_role_id`) | unset | Games → Global Config → Game Lobby Ping. The opt-in role the start-ping sweep mentions once per lobby-game launch (`feature_roles.GAME_LOBBY_PING`). Unset ⇒ the bot makes `@Game Lobbies` on the next lobby; "(none)" (stored `0`) ⇒ no lobby is announced. Same key the sweep reads, pinned by `tests/web/test_game_dials_are_enforced.py` |
| External tracking watches | unset | One or more (bot, channel, kind) pairs whose result messages are banked (set on Games → External Tracking); the same bot may appear in several channels |

### Per-channel (dashboard)

- **Channel allowlist**: only allowlisted channels accept any **party**-game command. It does not reach the duels and group elimination games, which gate on their own per-game `channel_allowlist` in `duel_config` and nothing else; their six panels say so. See `dk_pvp_games_suite_spec.md`. Nor does it reach dashboard-scheduled launches or feature-rotation rooms, which post where they were pointed (see "Scheduled launches"); the Global Config hint says which door it guards, not "party games can only be started in these channels".
- **LegitLibs `max_tier`**: hard cap on tier (default 4); higher requests silently downgrade.

### Environment / files

- No API key is needed for the question games: there is no AI fallback or per-game prompt file; every question game is bank-only.
- A LegitLibs starter pack of templates (`bot_modules/games/templates_seed.json`, `data.SEED_PATH`) is loaded into the shared global pool (`guild_id = 0`) on every boot, one `INSERT … WHERE NOT EXISTS` per template keyed on (global, title, body): a guild that has authored its own templates still gets the pack once, and re-runs add nothing. The file carries no ids: `template_id` is an INTEGER PRIMARY KEY the database assigns. The path must point at `data.SEED_PATH` (not the repo root), the rows must carry no string ids, and the seeder must not use a "skip if any published template exists" guard, which would hide both faults (trivia-tail-82). Tags are stored the way the dashboard stores them (comma-separated), and the gameplay reader accepts either that or a JSON list.
- The LegitLibs **blank vocabulary**: `legitlibs_blank_axes` (the parts of
  speech, and the domains and forms valid under each) and
  `legitlibs_blank_prompts` (the wording and examples a fill modal shows), is
  **seed content, edited by migration only**. It is read by `data.get_axes` /
  `data.get_prompts` and by `validate_template`, exposed read-only at
  `GET /api/games/legitlibs/axes` for the template editor's dropdowns, and has
  no create/update/delete surface anywhere. That is a **decision, not an
  oversight** (finding #91 of the config audit, closed won't-do): both tables are **bot-wide**, carrying no `guild_id` and listed
  in `guild_purge_service.GLOBAL_TABLES` as "Bot-wide by design", so any edit
  from any guild's dashboard would reword the prompts and re-gate the domains
  for **every** guild the bot is in, including guilds this instance does not
  run. Raising an axis's `min_tier` can also invalidate templates that are
  already published, because `validate_template` re-checks the tier rule at
  load. Nothing in Discord or on the dashboard claims this content is editable,
  so there is no unenforced promise to fix; the audit's own note recorded the
  cost of closing it as "a new CRUD surface with cascading pos/domain/form and
  min_tier rules: a feature, and a decision about who may reword the in-game
  prompts". **To revisit**, the cross-guild question has to be answered first,
  either per-guild rows (a `guild_id` column plus a fallback chain to the
  seeded set) or an explicit bot-owner-only surface, and published templates
  have to be revalidated when an axis tightens.
  `tests/web/test_games_legitlibs_vocabulary_is_seed_content.py` fails if
  any write path appears anywhere under `src/` outside a migration; it scans
  the SQL across the whole tree, not just the route modules, because the
  layering rule would put a spec-compliant editor's writes in
  `games/legitlibs/data.py` rather than in a route.

### In-memory

- The external-tracking watch cache (`guild → {(bot, channel) → kind}`) is warmed on load and refreshed by the dashboard through `GamesExternalCog.refresh_watch_cache` after every write, so the `on_message` hot path never touches the DB. A write that skipped that refresh would be a silent no-op until the next restart. Keyed on the pair, not the bot, so a bot playing in several channels is matched in all of them.
- A per-game payload lock serializes mutations within one game; the lock is freed on game close.

## Stored data

Per-guild content (the seeded question bank, LegitLibs templates and their revision history, AI-prompt overrides) plus per-game runtime state (the live game's payload, the session window, audit channel and editor-role settings, allowlisted channels, the anonymous-features audit trail and its retention setting) and an archive of every finished game's final payload. External-tracking config and raw banked bot messages are stored per guild. User ids appear inside game payloads and the history archive. Photo Challenge registers card metadata for the economy `photo_post` payout.

LegitLibs additionally stores a small vocabulary table (parts of speech, domains, forms) and per-blank prompt text used to render fill modals, plus an anti-repeat window of the last few templates used per guild, channel tier caps, and user-submitted abuse reports on filled-in answers.

No DM data is stored. No filesystem cache outside the prompt-config file and the LegitLibs seed file.

## Not Yet Built / Roadmap

The following were described as current behavior in earlier versions of this spec but are **not implemented today**. The underlying *capabilities* they described mostly still exist; they're just reached a different way now (usually the dashboard), or were removed outright. They're recorded here so the design intent isn't lost.

### Never-built or removed command surfaces

- **`/games allow-channel | disallow-channel | list-channels`**: no such slash commands exist. Channel allowlisting is real and enforced, but is managed from the web dashboard. Only the *slash-command interface* was ever documented; it was never wired. (The embed and logic helpers for these strings were deleted in the Components V2 conversion of `games/config/`; see the docstring of `games/config/layouts.py`.) A future slash interface for allowlisting is a reasonable roadmap item.
- **`/games audit-channel [channel]`**: likewise unbuilt as a slash command. The audit channel is a live feature, set from the dashboard (`games_audit_channel`).
- **`/games portal-grant | portal-revoke | portal-list`**: removed. The `games_portal_access` table these wrote was dropped in migration `041_drop_games_portal_access.sql`. Dashboard/Games access is now governed solely by Discord admin/mod permissions plus the `games_editor_role` (Game Host role); the editor role **supersedes** the old portal sign-in allowlist concept.
- **`/legitlibs-admin reload | cap-tier | preview | list | killswitch | enable`**: no such commands exist. LegitLibs content management, tier caps, and template preview live in the dashboard. The module-level **kill switch** described in older specs has been removed entirely (no `killswitch` code remains). LegitLibs tier caps are configured per channel from the dashboard, not via a slash command.

### Removed gameplay concepts

- **Consent system (`/consent`, `/consent-status`).** Fully deleted. The empty `games_consent/` directory went in `49a02867` and the orphan `games_consent` table (one row, zero code references) was dropped in migration 184. There is no per-user opt-in flag and no game blocks on consent. If per-user consent gating is ever revived, it would be a new build, not a re-enable of paused wiring. (Note: an unrelated "consent" system exists elsewhere (DM permissions) and is *not* part of the games suite.)
- **LegitLibs Hot Seat mode.** Older specs listed a third "Hot Seat" LegitLibs mode as a stub. It has been removed; only `classic` and `quiplash` exist today. A one-at-a-time LegitLibs variant could be revisited as a roadmap item.

### Collection-without-surface

- **External game leaderboards.** External tracking and the `games_external_messages` collector bank raw messages from external bots. **Economy payout is now built** (Gamebot CAH → `party_game`/`game_win`; Cat Bot catches → tiered `cat_catch`, § External tracking above), but our own *leaderboards/streaks* over those games (games-played, win-rate, catch counts by rarity) are still not surfaced; that is a roadmap item on top of the same banked data.
- **Hot Potato style points (metric tracked, never shown).** Every Hot Potato game already computes and accumulates **style points** (10 per second a player spends holding the potato in the danger zone, the last 30% of the timer) into `hot_potato_style (guild_id, user_id, total_points)` via `compute_style_points` + `add_style_points`. The per-game figure appears on the result card, and the same line quotes the player's **running total** ("now has 174 style points"; `get_style_total` in `duels/hot_potato/db.py` is the cumulative table's only reader). There is still no leaderboard, command or profile line; a fuller pass could track games played / wins / explosions (losses) / longest hold alongside it. This slots into the deferred participation-based cross-game standings roadmap (see memory: games progression roadmap) rather than being a one-off.
